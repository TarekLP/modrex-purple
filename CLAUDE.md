## Commands

```bash
npm run dev          # Start Electron app with HMR (main + renderer dev server)
npm run build        # Production build → out/
npm run preview      # Preview production build
npm run typecheck    # Type-check without emitting
npm run format       # Format all files with prettier
npm run format:check # Check formatting without writing
npm test             # Run tests once
npm run test:watch   # Run tests in watch mode
```

Run a single test file:

```bash
npx vitest run src/main/steam.test.ts
```

## Architecture

Electron app with three processes wired by `electron-vite`:

- **`src/main/`** — Node.js main process. All OS-level work lives here: API calls, file system operations, Steam registry reads, mod install/uninstall. No DOM access.
- **`src/preload/`** — Thin bridge. Exposes main-process functions to the renderer via `contextBridge`. Every new IPC handler in `index.ts` must also be exposed here and declared in `src/shared/api.d.ts`.
- **`src/renderer/`** — React + Tailwind UI. Communicates with main exclusively through IPC — never touches the file system or network directly.
- **`src/shared/`** — TypeScript types shared between main and renderer. `api.d.ts` declares the `window.api` surface; `types.ts` owns all domain interfaces.

### Main process modules

- **`api.ts`** — modworkshop REST API calls. `listMods`, `getMod`, `listModFiles`, `getLatestFile`, `listCategories`, `registerDownload`. All public GET endpoints, no auth token needed. Params sent as query string (Node fetch rejects GET with body). `getMod` returns the full mod object including `images`, `banner`, `dependencies`, `instructs_template`, and `tags` — these are optional fields on `Mod` not present in `listMods` results.
- **`download.ts`** — downloads a file to a temp path (`tmpdir()/pd3-mod-{uuid}.{ext}`). Accepts an optional `onProgress(downloaded, total)` callback; uses a `Transform` stream to count bytes as they arrive. `total` comes from `content-length` and is `0` if the server omits it — callers should handle the indeterminate case.
- **`steam.ts`** — finds PD3 install path by reading Windows registry (`HKLM\SOFTWARE\WOW6432Node\Valve\Steam`) and scanning `libraryfolders.vdf`. Also exports `findSteamPath()` which returns the Steam install directory (used to resolve `steam.exe` for direct process launch).
- **`settings.ts`** — reads/writes `settings.json` in `app.getPath('userData')`. Fields: `gamePath?` (manual override), `launchOptions?` (extra CLI args for PD3), `skipFileOpenLogWarning?` (suppress the `-fileopenlog` reminder), `dismissedDepsWarnings?` (array of mod IDs whose missing-deps warning has been permanently dismissed).
- **`mods.ts`** — mod file operations. Installs `.pak` files to `{gamePath}/PAYDAY3/Content/Paks/~mods/`, moves to `~mods/disabled/` on disable, removes on uninstall. Tracks state in a JSON file. Pure functions (`addToState`, `removeFromState`, `setEnabled`, `activeModPath`, `disabledModPath`, `stripPriorityPrefix`, `applyPriorityPrefix`) are exported separately for testing. `reconcileState` and `findUntrackedPaks` are **async** — they use `fs/promises` (`fsp.access`, `fsp.readdir`) to avoid blocking the main process event loop; `installMod`/`uninstallMod`/`enableMod`/`disableMod`/`reorderMods` remain sync (user-triggered, not in hot paths). `reconcileState` checks each state entry against disk on every `getInstalled` call, **marks missing files with `missing: true`** (does not drop them — user sees a warning badge instead of silent disappearance), clears the flag when the file is found again, and migrates any mods missing a `priority` field by assigning sequential values — skips all of this when `~mods.bak` exists. State is only written when missing flags actually change (`stateChanged` check). `findUntrackedPaks(gamePath, knownFilenames)` scans `~mods/` and `~mods/disabled/` for `.pak` files not in `knownFilenames`; returns early when `~mods.bak` exists. `installMod` reads the existing priority for a mod being updated (preserves it) or assigns `max+1` for new mods, prefixes the filename with `applyPriorityPrefix`, and cleans up the old file if the filename changed. `reorderMods(gamePath, statePath, orderedIds)` takes an ordered array of mod IDs (index 0 = highest priority), reassigns priorities as `total - pos`, renames `.pak` files on disk to match new prefixes, and saves state.
- **`index.ts`** — sets the window icon (`assets/icon.ico`, resolved via `join(__dirname, '../../assets/icon.ico')`). Registers all IPC handlers and caches `resolvedGamePath` at startup. On startup: restores `~mods.bak` → `~mods` if present. Also exposes `shell:open-external` for opening URLs in the system browser. DevTools toggle is Ctrl+Shift+I, dev builds only. `mods:install` falls back to `getLatestFile(modId)` when `mod.download` is null (some mods have `has_download: true` but a null `download` field); persists `fileId: file.id` in the installed state. `mods:install-file` accepts explicit `(modId, modName, fileId, downloadUrl, fileType, fileVersion, gamePath)` for installing a specific variant file; persists `fileId` in the installed state. `mods:get-installed` is async — after reconciling state it calls `findUntrackedPaks`, resolves numeric filenames via `getMod` (modworkshop metadata), assigns non-numeric filenames a deterministic negative ID via `hashFilename` (`-Math.abs(h) || -1`) with `stripPriorityPrefix(stem)` as the display name and version `'unknown'`, then persists and returns `{ mods, modsHidden }` — `modsHidden` is `true` when `{gamePath}/PAYDAY3/Content/~mods.bak` exists on disk. Untracked mods are absorbed into state on first detection and not re-processed on subsequent calls. `mods:reorder` calls `reorderMods(gamePath, statePath, orderedIds)`. `app:restore-mods` renames `~mods.bak` back to `~mods`; if both dirs somehow exist, it removes `~mods.bak` instead of throwing. `launchGame(launchOptions)` is a shared helper: when launch options are set and `steam.exe` is found it spawns `steam.exe -applaunch 1272080 {args}` (detached, avoids Steam's URI confirmation dialog); otherwise falls back to `steam://rungameid/1272080`. `settings:dismiss-deps-warning` appends a mod ID to `dismissedDepsWarnings` (deduped). `app:is-game-running` uses async `exec` (not `execSync`) so the `tasklist` call never blocks the main process event loop.

### Renderer components

- **`App.tsx`** — shell with TopBar + Sidebar + view switcher. Owns `installed: InstalledMod[]` as the single source of truth and `refreshInstalled` callback. Also owns `modsHidden: boolean` (set from `getInstalled()` response) and shows a yellow banner between TopBar and main content when true — banner appears on window focus via the `focus` event listener, not immediately after "Launch without mods" is clicked. `handleRestoreMods` calls `restoreMods()` IPC then re-fetches. Manages four views: `'browse'`, `'installed'`, `'settings'`, `'detail'`. **`BrowsePage` is conditionally rendered** (`{view === 'browse' && <BrowsePage />}`) — it unmounts when leaving Browse and mounts fresh on each visit so the tab switch is instant (the shell appears immediately with "Loading…", cards appear after the fetch). **`InstalledPage`** is wrapped in `React.memo` (`InstalledPageMemo`) and stays CSS-`hidden` when inactive — preserving its drag state, `localOrder`, and `fetchedAt` tracking across tab switches. `SettingsPage` is also CSS-`hidden` when inactive. Navigation uses a `detailStack: number[]`. `openDetail(modId, from)` resets the stack to `[modId]` and records `prevView`. `pushDetail(modId)` appends to the stack (navigating to a dependency). `closeDetail()` pops the stack; only returns to `prevView` when the stack empties. All entries in `detailStack` are rendered as `ModDetailPage` instances simultaneously — only the top is visible, the rest are CSS-hidden. This preserves tab and scroll state when navigating back through the dep chain. `ModDetailPage` receives `isActive` (true only for the top of the stack) to gate its keyboard event handlers. Navigation callbacks (`openDetailFromBrowse`, `openDetailFromInstalled`, `openDetail`, `pushDetail`) are stable `useCallback` references.
- **`components/TopBar.tsx`** — fixed header with the "PD3 Mod Manager" title on the left and game controls on the right. Polls `isGameRunning` every 3s. When `PAYDAY3-Win64-Shipping.exe` is detected: shows a "Stop game" button. Otherwise: shows "Launch modded" and "Launch without mods". "Launch without mods" renames `~mods` → `PAYDAY3/Content/~mods.bak` (one level above `Paks/`) before opening Steam — must be outside `Paks/` because UE5 scans all subdirectories there. Does NOT call `onRefreshInstalled` immediately after launch — the mods-hidden banner in App appears on the next window focus event instead, avoiding confusing the user right after they intentionally clicked the button. When the game exits, `restoreMods()` is called automatically and `onRefreshInstalled` runs. Game detection uses `tasklist /FI` — note that Windows truncates process names at 25 chars, so the check is for `PAYDAY3-Win64-Shipping` (not the full `.exe`). "Launch modded" calls `getSettings()` first: if `-fileopenlog` is absent and `skipFileOpenLogWarning` is not set, a custom styled warning modal appears with a "Don't show again" checkbox — checking it saves `skipFileOpenLogWarning: true` to settings.
- **`components/Sidebar.tsx`** — nav between Browse, Installed, and Settings views. Uses its own `NavView = 'browse' | 'installed' | 'settings'` type (not the full `View` from App) so the detail view doesn't leak into it. Has a collapse toggle at the bottom; collapsed state shrinks to `w-12`. Labels fade out via opacity transition — always in the DOM, never conditionally rendered — and `overflow-hidden` on the aside clips them as the width animates. The collapse chevron rotates 180° via CSS transform.
- **`components/SettingsPage.tsx`** — two sections: **Game Path** (shows detected/manual path, Browse button opens native folder picker, Reset returns to auto-detect) and **Launch Options** (monospace text input, auto-saves 500ms after typing via debounced `useEffect`; skips the initial save using a `launchOptionsLoaded` ref). Describes `-fileopenlog` as required for mods.
- **`components/BrowsePage.tsx`** — paginated mod grid with search, category filter, and sort. Mounts fresh on each visit (see App.tsx). Receives `installed`, `onRefreshInstalled`, and `onOpenDetail` as props. Calls `onRefreshInstalled` after any install/uninstall/enable/disable. Owns a single `onDownloadProgress` listener (one per page, not one per card); passes `progress` down only to the card with `loading === true`. `fetchMods` wraps `setResult(data)` and `setLoadingMods(false)` together inside `startTransition` — the page shows "Loading…" instantly and the 24-card render is deferred to a non-blocking frame. On Install click: always fetches full mod via `getCachedMod` first. If `mod.download === null` and the mod has more than one file, fetches the file list via `getCachedModFiles` and shows `FileSelectModal` — `setLoadingMod(null)` is called explicitly before opening the modal so the install button never flashes. Otherwise checks for missing required deps and shows `DepsWarningModal` if any exist and haven't been dismissed — same explicit `setLoadingMod(null)` before showing.
- **`components/InstalledPage.tsx`** — receives `installed` as a prop; fetches full `Mod` data from the API for each installed mod and renders either `ModCard` (grid) or `ModListRow` (list). View mode toggled via `LayoutGrid`/`List` icon buttons in the header; preference persisted to `localStorage` under key `pd3mm:installed-view`, defaults to `'grid'`. Mod metadata tracking uses `fetchedAt: useRef<Map<number, number>>` (id → timestamp) — a `useEffect([installed])` re-fetches any mod whose entry is missing or older than 5 minutes, so update detection stays fresh across long sessions without polling. Failed fetches (e.g. negative IDs for non-modworkshop mods) are tracked in `failedIds` state so those cards/rows still render using `syntheticMod(ins)` — a minimal `Mod` built from `InstalledMod` fields with no thumbnail, `user: { name: 'Unknown' }`, and `has_download: false`. `onOpen` is a no-op for synthetic mods (no detail page). Detects updates by comparing `installed.version` vs `mod.version`; shows a banner and modal with per-mod checkboxes + "Update Selected" when updates exist. Maintains `localOrder: number[]` (mod IDs sorted by `priority` desc) synced from `installed` via `useEffect` — both grid and list render from `localOrder`, not directly from `installed`. Both views are rendered inside an IIFE that pre-builds `installedMap = new Map(installed.map(m => [m.id, m]))` and pre-computes `draggedIdx = localOrder.indexOf(draggedId ?? -1)` once per render (avoids O(n²) lookups inside the flatMap). Both views support HTML5 drag-to-reorder with insertion indicators: `draggedId` / `dragOverId` / `dragOverPos` state; `handleDragOver`/`handleDrop` serve the list view; `handleGridDragOver`/`handleGridDrop` serve the grid view. Drop handlers debounce indicator updates via `dragOverId !== id` and `dragOverPos !== pos` guards; dropping on self is a no-op. **List view** indicator: `flatMap` inserts a thin `h-0.5 bg-accent` line before or after the hovered row — direction determined by comparing `draggedIdx` vs `thisIdx`. **Grid view** indicator: an absolutely-positioned `w-1 bg-accent` bar (`pointer-events-none`) anchored to the left or right edge of the hovered card wrapper — never inserted into the grid flow so it cannot intercept `dragover` events. Both `handleGridDragOver` and `handleGridDrop` compute the before/after position independently from `e.clientX - rect.left < rect.width / 2` at event time, so there is no stale-state dependency between them.
- **`components/ModListRow.tsx`** — list-view alternative to `ModCard` for the installed page. Full-width horizontal row: thumbnail (`w-28`), mod name + "By [author]" + version, toggle + trash button side-by-side on the right. The entire row is `draggable` — no separate grip handle. `isDragging` applies `opacity-40`. Uses `group` for hover effects — `group-hover:brightness-110` / `group-hover:grayscale-0` on thumbnail, `group-hover:text-accent-bright` on name. When `installed.missing` is true, shows a yellow "File missing" badge and disables the toggle (enable/disable makes no sense without a file on disk); trash button stays active to allow removing the dead state entry. Only used by `InstalledPage` in list mode; never shown in `BrowsePage`.
- **`components/ModDetailPage.tsx`** — full-page detail view for a single mod. Fetches via `getCachedMod` + `getCachedModFiles` in parallel on mount (both 5-min TTL cached). Four tabs: **Description** (mod.desc + changelog + license, rendered as Markdown), **Images** (grid from `mod.images`, click opens lightbox), **Downloads** (file list — each row has an "Install" button for in-app install and a "Download ↗" button to open in browser; the Install button shows "Installed" in green and is disabled when `installedMod.fileId === file.id`), **Dependencies & Instructions** (`mod.instructs_template.instructions` as Markdown + required/optional dependency cards with inline Install buttons). The sticky top bar holds Install button (when not installed) or a `Toggle` (enable/disable) + icon-only trash button (remove) when installed. On Install click: if `mod.download === null` and there are multiple files, shows `FileSelectModal` for variant selection. Otherwise checks for missing required deps and shows `DepsWarningModal` if any exist and haven't been dismissed (session via `sessionStorage`, permanent via `dismissedDepsWarnings` setting). Subscribes to `window.api.onDownloadProgress` **only when `isActive` is true** — hidden pages in the dep-chain stack unsubscribe automatically; the effect re-subscribes when the page becomes active again. Shows a thin progress bar below the top bar and updates button labels with percentage during download; auto-clears 800ms after the last event. Uses `react-markdown` via the `MarkdownContent` component for all Markdown rendering. Links in rendered Markdown are intercepted and opened via `window.api.openExternal`. Accepts optional `onOpenDetail(modId)` — when provided, dependency cards in the deps tab are fully clickable (navigates in-app); each card also has an icon-only `ExternalLink` button that opens the mod page in the browser. Install buttons inside dep cards use `e.stopPropagation()` to prevent the card click from firing.
- **`components/FileSelectModal.tsx`** — modal for mods that have multiple variant files (`mod.download === null`). Lists all files with type badge, size, version/label, per-file Install and external-download buttons, and a download progress bar. Subscribes to `onDownloadProgress` internally. Disables all other Install buttons while one is in progress (`!!installingId`). Auto-closes on successful install. Backdrop-click and Escape both dismiss it. Used by both `BrowsePage` and `ModDetailPage`. `isInstalled` per row is determined by `installedMod?.fileId === file.id`.
- **`components/DepsWarningModal.tsx`** — shared modal that lists missing required dependencies with per-dep Install buttons. Props: `modId`, `missingRequired`, `gamePath`, `onRefreshInstalled`, `onClose` (X button — temporary dismiss), `onGotIt(permanent: boolean)` (caller handles session + optional persistent dismiss). Auto-closes when `missingRequired.length` reaches 0 (all deps installed). Internal state: `dontShowAgain` checkbox, `installingDeps` map. Used by both `BrowsePage` and `ModDetailPage`. Checkbox uses `div onClick` + `pointer-events-none` on the `<input>` to avoid the implicit `<label>` click-area overlap problem.
- **`components/ModCard.tsx`** — shared card used by both BrowsePage and InstalledPage. The top section (thumbnail + name + description) is a clickable area that calls `onOpen` to navigate to the detail page. The bottom action row is separate and does not propagate the click. For uninstalled mods it shows likes/downloads/views/last-updated with icons (counts formatted via `formatCount` — e.g. `1.2k`; time formatted via `formatRelativeTime` using `mod.bumped_at` — e.g. `5m ago`, `3h ago`, `7d ago`, `2mo ago`, `1y ago`) and an Install button. For installed mods it shows the version number, a `Toggle` (enable/disable), and an icon-only trash button (remove); when `installed.missing` is true, also shows a yellow "File missing" badge and disables the toggle. Does **not** subscribe to `onDownloadProgress` internally — receives `progress?: { downloaded, total } | null` as a prop instead (parent passes it only to the card with `loading === true`, avoiding 24 listeners per browse page). Renders a thin progress bar along the bottom edge and shows percentage in the Install button label when `loading === true`.
- **`components/Select.tsx`** — reusable custom dropdown. Use this instead of native `<select>` — native selects render with OS chrome that can't be themed.
- **`components/Toggle.tsx`** — pill-shaped switch for boolean state (enabled/disabled). Uses `bg-accent` when on, `bg-surface-active` when off. Accepts `checked`, `onChange`, `disabled`.
- **`modCache.ts`** — session cache with a **5-minute TTL** for both mod metadata and file lists. `getCachedMod(id)` serves from cache if the entry is younger than 5 minutes, otherwise re-fetches via `window.api.getMod`. `getCachedModFiles(id)` does the same for file lists via `window.api.listModFiles`. Used by `BrowsePage`, `InstalledPage`, and `ModDetailPage` — never call `window.api.getMod` or `window.api.listModFiles` directly from the renderer. The TTL ensures update detection in `InstalledPage` stays fresh across long sessions without explicit polling.

### Styling

All colors are defined as semantic tokens in `src/renderer/src/index.css` via Tailwind v4's `@theme` block — never use hardcoded Tailwind color classes like `zinc-*` or `red-*` in components. Token names: `surface`, `surface-raised`, `surface-hover`, `surface-active`, `surface-light`, `border`, `text`, `text-muted`, `text-subtle`, `accent`, `accent-bright`, `danger`, `danger-hover`, `danger-text`, `success`, `success-text`.

Icons use `lucide-react`. Import individual icons by name — do not use a barrel import.

Markdown is rendered with `react-markdown` (not `marked`). The `MarkdownContent` component in `ModDetailPage.tsx` wires per-element Tailwind classes and routes link clicks through `window.api.openExternal`. No `dangerouslySetInnerHTML` anywhere in the codebase.

### Key domain facts

- **modworkshop game ID for PD3 is `853`** — hardcoded in `api.ts`.
- The modworkshop API at `api.modworkshop.net` requires a `User-Agent` header or returns 403.
- All mod images (thumbnails, banners, gallery images) share the same URL base: `${THUMBNAIL_BASE_URL}/${file}` where `THUMBNAIL_BASE_URL = 'https://storage.modworkshop.net/mods/images'` (exported from `src/shared/types.ts`). The `banner` field is a wider landscape image; `thumbnail` is the square card image; `images` is the full gallery array (includes both).
- Mod descriptions and installation instructions from the API are **Markdown**, not HTML. Render with `react-markdown` via the `MarkdownContent` component.
- PD3 mods are `.pak` files. Active path: `{gamePath}/PAYDAY3/Content/Paks/~mods/`. Disabled path: `{gamePath}/PAYDAY3/Content/Paks/~mods/disabled/`. The `gamePath` is the Steam library root (`steamapps/common/PAYDAY3`); game content lives one level deeper in the `PAYDAY3/` subdirectory.
- Mods installed via the app use `pakFilename(modName)` to derive the base filename — sanitizes the mod name (collapse non-word chars to `_`, strip leading/trailing underscores, append `.pak`), e.g. `CSA-39_Assault_Rifle.pak`. The actual filename on disk is always prefixed with the priority number: `applyPriorityPrefix(base, priority)` → `003_CSA-39_Assault_Rifle.pak`. `stripPriorityPrefix` removes the `\d+_` prefix; `applyPriorityPrefix` re-applies it after stripping (safe to call on an already-prefixed name). Manually placed mods may have any filename; non-numeric filenames are tracked with a synthetic negative ID and cannot be re-resolved via the API. Their display name strips the priority prefix so `001_MyMod.pak` shows as `MyMod`.
- **Mod priority and load order**: UE5 loads `.pak` files alphabetically within `~mods/`, so higher prefix number = loads later = overrides earlier mods. `InstalledMod.priority` (higher int = higher priority) maps to the prefix. Top of the `InstalledPage` list = highest priority. `reorderMods` assigns `priority = total - position` (position 0 = top = priority `total`).
- `InstalledMod` has optional `fileId?: number` (modworkshop file ID, set by both install handlers; absent for manually placed mods), `priority?: number` (absent for legacy installs; `reconcileState` migrates these on first `getInstalled` call), and `missing?: boolean` (set by `reconcileState` when the `.pak` file is not found on disk; cleared when the file reappears). Use `installedMod?.fileId === file.id` to identify which variant is installed — do not use version string comparison, variant files often share the same version.
- Anti-cheat (Nebula) is not a concern — mods work online freely.

## Testing

Tests live in `src/main/` only — the renderer has no tests. Vitest runs in a Node environment (no DOM). All test files match `src/**/*.test.ts`.

## Workflow

- Commits must follow conventional commits: `type(scope): subject` — enforced by commitlint (the hook rejects non-conforming messages)
- Keep commits focused — one logical change per commit
- When writing tests + implementation, commit tests first before writing implementation
